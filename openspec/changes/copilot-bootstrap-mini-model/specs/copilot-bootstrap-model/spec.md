## ADDED Requirements

### Requirement: Copilot turns bootstrap on a fixed mini model
The system SHALL use `github-copilot/gpt-5.4-mini` for a hidden first user-initiated model call in a GitHub Copilot turn when that model is available.

#### Scenario: First Copilot step uses bootstrap model
- **WHEN** a user starts a new turn with GitHub Copilot selected and `gpt-5.4-mini` is available
- **THEN** the first internal model call in that turn uses `github-copilot/gpt-5.4-mini` instead of the currently selected model

### Requirement: Selected model remains the user-visible model
The system SHALL keep the currently selected model as the model that produces the user-visible assistant response for the turn.

#### Scenario: Visible response comes from selected model
- **WHEN** a GitHub Copilot turn starts with a hidden bootstrap call on `gpt-5.4-mini`
- **THEN** the assistant response surfaced back to the user is generated by the selected model rather than the bootstrap model

### Requirement: Follow-up iterations return to the selected model
The system SHALL use the currently selected model for iterations after the bootstrap call in the same Copilot interaction.

#### Scenario: Tool loop switches back after bootstrap
- **WHEN** the bootstrap call produces a tool request and the turn continues to a second model iteration
- **THEN** the second and later model calls use the user-selected model for that session

### Requirement: Bootstrap and follow-up calls share one interaction identity
The system SHALL reuse the same interaction identifier across the bootstrap call and all later model calls in the same turn.

#### Scenario: Interaction ID remains stable across model switch
- **WHEN** a turn starts on `gpt-5.4-mini` and later iterations run on the selected model
- **THEN** all requests in that turn use the same Copilot interaction identifier

### Requirement: Bootstrap override falls back safely
The system SHALL skip the bootstrap override and use the selected model for the whole turn when `github-copilot/gpt-5.4-mini` is unavailable.

#### Scenario: Missing bootstrap model
- **WHEN** the current provider is GitHub Copilot but `gpt-5.4-mini` is not present in the resolved model list
- **THEN** the system uses the selected model for the first and later calls in the turn

### Requirement: Non-Copilot turns are unchanged
The system SHALL keep existing model-selection behavior for providers other than GitHub Copilot.

#### Scenario: Non-Copilot provider ignores bootstrap logic
- **WHEN** a user starts a turn with a non-Copilot provider selected
- **THEN** the system uses the selected model for all calls in that turn without applying the mini-model bootstrap override
